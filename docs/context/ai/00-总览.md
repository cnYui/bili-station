## 一句话现状

CLI 从「7 个命令各自 60–150 行、参数散在三处」变成「声明式注册表 + 统一管线」，
新增能力是勾开关而不是抄样板。测试从 122 条涨到 214 条，其中 92 条是新的 CLI 层
断言，**全部不需要 Chrome**。

## 最重要的三条

1. **`order.mjs` 顶部那段推导是整个排序功能的地基**，而且已被 `probe fav-order`
   实测确认。改排序相关代码前先读它。

2. **B 站对不存在的 tagid 返回 code 0「OK」**（见 [03-探针实测.md](03-探针实测.md)）。
   配合 `setUserTags` 的覆盖语义，传错 id 会**静默清空**那个人的分组，
   而且不报任何错。`validateTagIds()` 这道校验不能省。

   （顺带：特别关注的 22117 是「特殊关注达到上限」，**是配额不是不可写**。
   第一轮判错过一次，订正记录在 03。）

3. **测试隔离在 Windows 上必须用 `os.tmpdir()`**，不能用 Git Bash 的 `/tmp`。
   `BILI_STATION_DIR=/tmp/xxx` 在 Windows 上 Node 看不到那个路径，会**静默回退
   到真实数据目录**。我在重构中间就是这么误操作到真账号的，详见
   [02-已修缺陷.md](02-已修缺陷.md) 末尾。

## 命令表面

```
status                     连接 / 登录态 / 收藏夹 / 探针结果
folders  [list|create|setup]
scan     [fav|follow|uploads|sample]
sort     候选夹分类（核心）           [写][排序]
merge    合并收藏夹                   [写][排序]
dead     失效视频归档/移除            [写][排序]
follow   [list|add|remove|set|tag]    [写][选择器]
unfollow 规则批量取关                 [写]
probe    [fav-order|relation-act|list] 实测 B 站行为
schema   机器可读的全部命令定义
```

退出码：`0 成功 / 1 错误 / 2 风控中止 / 3 登录失效 / 4 无事可做 / 5 参数错误`。
第 5 个是新增的——对 agent 来说「参数写错」是可自我修正的失败，必须和运行时错误分开。
