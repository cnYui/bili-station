# P1：已修的缺陷

每条都是重构前**可复现**的问题，不是代码风格意见。别改回去。

## 1. `sort` 绕过缓存归一化函数

**原状**：`cli.mjs:375/388` 自己 `store.read('favorites.json')` + `new Map(cached.items)`，
而 `scan` / `merge` / `dead` 走 `loadCache()`。同一份缓存两个读者、两套归一化。

**后果**：旧格式（裸数组）的缓存在 `sort` 里 `itemsOf()` 取不到 `.items`，
返回空数组 → 静默触发一次全量重扫。大夹约 7 分钟。不崩，所以一直没人发现。

**修法**：`src/cli/favcache.mjs` 成为收藏夹缓存的**唯一**读写入口，
`loadCache / saveCache / itemsOf / scanFolder / scanMany` 全在里面。
所有命令走同一个函数。

这是项目早先那个「Spread syntax requires ...iterable」崩溃的同一类问题的残留——
上次只把 `itemsOf()` 统一了，Map 的构造和写回还是各写各的。

## 2. `server.mjs` 的配置默认值只在文件不存在时生效

**原状**：`store.read('config.json', DEFAULTS)` —— 第二个参数是 fallback，
**只在文件读不到时用**。

**后果**：用户手改出一个局部 `config.json`（比如只写 `{"cdpPort":9333}`），
`server.mjs:98` 的 `c.ai.apiKey` 直接 TypeError，`/api/status` 整个挂掉。
CLI 侧一直是 spread 逐键兜底，两个入口行为不一致。

**修法**：server 的 `cfg()` 改成 spread 逐键兜底，和 CLI 对齐。

## 3. boolean flag 吞掉位置参数

**原状**：解析器不知道类型，见到 `--yes` 就看下一个 token 是不是 `--` 开头，
不是就当成它的值。

**复现**：`folders create --yes "A,B"` → `flags.yes = "A,B"`，名字列表为空，直接报错。
文档里写的顺序（`folders create "A,B" --yes`）是对的，反过来写就静默错位。

**修法**：`args.mjs` 的 `CONSUMES` 表。`boolean` 类型永不消费下一个 token。

## 4. help 漏了 5 个已实现的 flag

`scan --refresh` / `scan --page-delay` / `scan sample --out` /
`sample --page-delay` / `merge --page-delay`。

**修法**：help 从注册表生成，声明即文档。物理上不可能再漏。

## 5. `--inactive-days` / `--only-inactive` 在 CLI 下恒失效

**原状**：它们读 `uploads.json`，而这个文件**只有 Web UI 的
`POST /api/scan/uploads` 会写**。CLI 没有任何命令能生成它。

**后果**：纯 CLI 流程下这两个 flag 恒定命中 0 个目标，`--only-inactive`
直接退出码 4。help 里写着两个骗人的参数。

**修法**：新增 `scan uploads`，补上生产者。边查边存（每 25 个落一次盘），
中断不白跑。`unfollow` 在缺数据时给出**明确原因**而不是静默返回 0 个：

```
没有投稿时间数据，无法判断停更。先跑 bili-station scan uploads
```

## 6. `createTag` 的端点是 404

**原状**：`/x/relation/tag/add` —— 实测返回 `non-JSON response (HTTP 404)`。
正确端点是 `/x/relation/tag/create`。

这条路径此前在 CLI 和 Web UI 都没有入口（`buildTagOps` 在 server 里只有执行端、
没有生成端），所以从来没被调用过，也就一直没暴露。

顺带实测出：**分组名不允许含特殊字符**，下划线会被 22101 拒绝。

## 7. 顺带补上的能力

- `unfollow --protect-tag`：`planUnfollow` 一直支持 `protectTags`，CLI 从没暴露过
- `bili.deleteFolders()`：删收藏夹的 API 原本没有（清理误建的夹时才发现缺）
- `bili.tagUsers(tagid)`：读任意分组的成员，`specialFollowings()` 改为复用它

## 操作教训：Windows 上的测试隔离

**`BILI_STATION_DIR=/tmp/xxx`（Git Bash 的 mktemp 路径）在 Windows 上无效。**
Node 看不到那个路径，`store.read` 读不到文件就回退默认值，**整个隔离静默失效**，
实际跑的是真实数据目录。

我在重构中途就是这么误操作的：以为已经隔离，跑了
`folders create --yes "A,B"`，在真账号上建了两个空夹（已用新加的
`deleteFolders` 清掉，两个夹都是 0 条，无数据丢失）。

**正确做法**：用 Node 的 `os.tmpdir()`。两个测试文件都是这么写的：

```js
process.env.BILI_STATION_DIR = mkdtempSync(join(tmpdir(), 'bili-station-test-'));
```

**更硬的规矩**：写命令的测试一律用假后端跑 `plan()`，不要对真账号加 `--yes`。
`test-cli.mjs` 的 `makeCtx()` 就是为这个准备的。
